Why this test is misleading CF asymmetry

  • CloudFlare was caching one side and not the other. Inspecting headers later showed dev/articles had cf-cache-status: HIT, age=2579 (CF served from edge) while dev2/articles had cf-cache-status: DYNAMIC (CF tunneled every request to origin). dev2 had no CF Page Rule for "Cache Everything" while dev did.
  • So dev's apparent "win" on req/s came from CF, not from the Redis stack. Varnish was actually HITting at origin (x-varnish-hits: 5005), but the client paid the full client → CF → origin round-trip for every request.
  • Even with that handicap, Varnish still won the tail decisively: P90 756 ms vs 1,620 ms, P95 1,173 ms vs 1,986 ms.
  • The next tab (Direct origin) reruns with CF disabled — apples-to-apples.

What the data shows CF disabled — clean origin compare

  • Homepage: Varnish wins on every metric. 2.39× throughput, 3.75× faster P50, even P99 is 55% faster. Both stacks are now reaching origin directly so the comparison is fair.
  • /articles: Varnish wins throughput and median. 1.46× req/s, 2.78× faster P50 (297 ms vs 825 ms), 1.98× better average. 89.5% of all responses came back under 800 ms.
  • But Varnish has a worse P90+ on /articles. A bump of 458 requests landed in the 1.15–1.51 s bucket — these are cold-MISSes that piled up in PHP-FPM when Varnish handed them off all at once. Once they completed they warmed cache, so future bursts wouldn't repeat. The Redis stack has a TIGHTER distribution (everything clusters in 0.79–0.95 s) but the entire distribution is shifted to slower territory — so the median is bad, but the variance is small.
  • "Tight and slow" vs "fast with a tail" — both have their merits. Redis stack guarantees ~0.9 s for every request. Varnish gives ~0.3 s for 90% of users and ~1.2 s for the unlucky 10% who hit a cold key during a traffic burst. For real traffic patterns Varnish wins because the cold cache is a one-time cost, and warm-cache requests dominate. The benchmark's -c 500 cold start is the worst case for it.
These tests bypass Cloudflare entirely (CF was disabled at the proxy/DNS level for the duration of the run). Numbers represent the actual speed of origin server in each configuration. In production, CF in front of Varnish absorbs most of this load — the comparison above is "what reaches the origin when CF misses."
